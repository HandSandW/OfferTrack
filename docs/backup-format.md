# OfferTrack 完整备份格式 v1

此格式由 `backup_archive.rs` 定义；扩展名 `.offertrack-backup`，非 ZIP、未压缩、未加密。仅普通文件和目录，不保存执行指令、链接、ACL、NTFS 数据流或文件系统时间/属性。核心记录时间在数据库中保留。

## 字节布局

1. 16 字节 ASCII magic：`OFFERTRACK-FULL1`，没有换行。
2. 8 字节无符号小端整数：随后 JSON 清单的 UTF-8 字节数。
3. 指定长度的 JSON 清单（逻辑 `manifest.json`）。
4. 按清单 entries 数组顺序排列的文件原始内容；目录占零字节，无额外分隔或尾部数据。

清单字段采用 camelCase：version=1、kind=full、warehouseFormat=1、warehouseId、schemaVersion、createdAtUtc、includesRecycleBin、entries。每个 entry 为 path（`/` 分隔相对路径）、directory、sizeBytes、sha256；目录长度为 0，哈希为空字符串。文件哈希为小写十六进制 SHA-256，空文件也需正确哈希。entries 使用数组以便拒绝重复路径，而非 JSON 对象静默合并同名键。

必须有普通文件 `offertrack.sqlite`。每条路径的父目录须显式出现在清单中；写出按路径排序，读取可接受任意顺序。目录先按深度建立，文件 payload 始终依原 entries 顺序读取。包实际长度必须恰等于 24 + 清单长度 + 全部文件长度。

## 校验与边界

- 清单不超过 32 MiB，条目最多 100,000；路径不超过 4096 UTF-8 字节及 128 个片段。超限明确拒绝，不能静默截断。
- 拒绝未知字段、未支持版本、错误仓库/schema 格式、非法时间、错误哈希或长度溢出。
- 拒绝绝对路径、`.`/`..`、反斜杠、控制字符、Windows 非法字符/保留设备名、尾部空格/点、NTFS 数据流和大小写折叠重复路径。
- 父路径必须是目录，不能通过文件/目录混用跳出提取根目录；不保存或提取符号链接/目录联接点/重解析点。
- 根层不允许活动 SQLite sidecar、写锁或 `warehouse.json`；描述文件从清单重建。不含回收站时拒绝任何回收站条目。
- 文件按 64 KiB 缓冲流式校验，不把附件整体加载进内存。SHA-256 能检测意外损坏，不是数字签名或来源认证；不要恢复不可信来源的包。
- 完整包初步预览校验全部 payload 和整个包哈希。恢复再次校验用户确认的包哈希，再到全新目录提取、复核落盘字节、检查 SQLite、升级副本；所有步骤成功才发布新仓库。不会覆盖原仓库。

## 保存范围和身份

数据库来自 SQLite 一致性快照，包含视图、模板、配置、历史及文件索引。包含 attachments、隐藏/未关联/空目录、历史数据库备份、Agent 交换目录及其他普通仓库文件；活动数据库/sidecar、写锁和描述文件不直接复制。若有先前生成的 Agent 派生快照，其中绝对路径可能过期，Agent 功能接入后必须在新位置重新生成。

完整恢复与迁移沿用逻辑 warehouseId，使历史数据库备份仍可用；物理副本独立，不同步。数据库单独恢复沿用其既有“新 ID”约定。排除回收站只排除文件树，已删除记录元信息仍保留；原本已缺失的附件不会凭空恢复。

迁移先生成 beforeMigration 数据库快照和完整包，再从该包恢复到新目录。完整包和原仓库保留，验证后由用户确认切换；需要原文件之外约两份副本的空间。新建备份/迁移只允许可写会话，并拒绝未完成的复制/移动日志。

失败的 `.offertrack-backup-UUID.pending` 和 `.offertrack-restoring-UUID` 不自动删除，不冒充成功产物；目前没有续传或中途取消。不要在备份、恢复或迁移期间外部编辑/移动文件。本方案不声称能防御任意外部进程持续并发破坏，或保证物理断电后的存储设备持久性。
