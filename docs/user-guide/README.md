# OfferTrack 用户指南

> 当前版本：0.1.0 开发版。本文是应用内离线帮助和后续公开用户文档的单一内容来源。先使用测试数据，不把开发构建当作唯一数据副本。

## 快速开始

1. 将 OfferTrack 和 offertrack-cli 两个程序放在同一文件夹，启动 OfferTrack；界面是独立桌面应用，日常使用无需联网。
2. 在可靠本地磁盘新建空文件夹作为数据仓库，通过“新建仓库”连接。程序目录与仓库可以分开。
3. 到“投递记录 → 新建投递”填写公司、岗位。新建不等于已投递；创建日期显示年月日、底层保存精确时间，默认按创建时间倒序。
4. 点记录打开详情，保存资料。在“文件”打开对应文件夹放入简历；每条记录都有独立副本，允许子目录。
5. 实际投递后在“流程”改为“已投递”，首次自动填当天投递日期。以后维护阶段、辅助状态和面试轮次。最终成功是 Offer，失败是已挂。
6. 在概览查看提醒、点击数字定位记录；在“待办与日程”安排求职事项。设置中可调整提醒阈值、每页默认条数与主题。
7. 定期做包含简历的完整备份，另存可靠磁盘。数据库自动备份不含简历正文。

表格可用方向键、Home/End 和 Tab 移动焦点；Enter/F2 编辑当前格，Shift+Enter 打开详情。Ctrl+C 复制完整格值，Ctrl+V 把一个文本值放入编辑器等待确认，不会把多行多列自动拆成多条记录。保存后可用 Ctrl+Z 或“撤销单格修改”撤销最近一次单格保存；若记录随后已被详情、Agent 或其他操作修改，撤销会拒绝覆盖。进度与附件仍从详情操作，文件操作不属于单格撤销。

## 使用帮助窗口

F1 或侧栏“帮助”打开独立的完整手册窗口，不切换主页面、不丢弃正在编辑的表单。点击主页面顶部“本页帮助”定位对应章节；帮助菜单另有快速开始、快捷键、数据与文件、常见问题、诊断和关于入口。

左侧目录可按标题或全文搜索（多个空格分隔关键词须全部匹配），点击结果阅读完整章节。右侧“后退/前进”保留窗口内阅读历史；搜索结果不会修改投递筛选。正文链接只在内置章节与附录之间跳转，外部网址仅显示文本，不自动联网或运行命令。Agent 接口及完整备份格式附录随应用打包。

关闭帮助只关闭帮助窗口；关闭主窗口仍检查未保存修改，确认退出后帮助一并关闭。帮助可在无仓库、只读或后台业务操作期间使用。主题跟随本机外观设置。

## 快捷键

- F1：打开完整使用手册；帮助窗口内返回快速开始。
- 帮助窗口 Ctrl+F：聚焦全文搜索；Alt+左/右：阅读历史后退/前进。
- Tab / Shift+Tab：移动控件焦点；Enter / 空格：操作当前按钮。
- Ctrl+点击网址：使用系统默认浏览器；新标签页或窗口由浏览器决定。
- 文件双击：默认应用打开；右键或“更多”：其他打开方式。
- 弹窗 Escape：尝试取消，有未保存修改时仍需确认；处理中不会强制取消。
- 打开方式菜单方向键、Home/End、Escape：选择及关闭菜单。
- 文本框 Ctrl+C / Ctrl+V：复制粘贴；不代表已实现整行复制、表格即时编辑或全局撤销。

## 数据与文件说明

warehouse.json 是仓库描述，offertrack.sqlite 保存元数据，applications 存每条投递的独立文件夹，backups 存数据库备份，recycle-bin 是 OfferTrack 回收站，agent-access 存私人派生快照。不要手动编辑数据库、描述、清单或临时日志。

投递目录名包含创建日期及时间、公司、岗位和短 ID，便于文件管理器按名称排序；显示日期与底层精确时间并不相同。直接复制整个仓库时应先关闭应用和其他写入者，勿只复制正在使用的 SQLite 主文件而遗漏 WAL。优先使用应用的完整备份。

可以在 applications 内管理普通文件、子目录及未关联文件夹。认领使用确认新建记录的时间，不使用目录原始创建时间；任意名称可认领后规范化，占用时保留原路径等待重试。切换仓库只是打开另一套数据，迁移会复制并校验完整内容，原目录保留。

## 常见问题

### 没看到文件或投递，是丢失了吗？

先清除搜索、筛选、概览限定范围，检查已归档和回收站。加载失败不是“零条”。文件页检查目录再重新扫描；缺失索引不等于永久删除，恢复到原相对路径可重新识别。只读模式不会刷新索引。

### 提示占用、只读或版本冲突怎么办？

关闭正在写入同一仓库的其他实例或文档程序，再重试；不要删除锁文件强行解除。只读可查看但不能修改。版本冲突时先复制保留输入，再取消并重新读取；不自动合并。

### 备份或恢复失败怎么办？

保留源仓库、备份及失败暂存。核对磁盘空间、占用、版本和错误说明，不修改哈希清单来强行通过。恢复永远创建新目录；数据库快照没有简历正文，完整包才包含文件。只有当前固定回收站的已识别子项可永久清理，应用没有任意路径删除按钮。

### Agent 连不上或不能写入怎么办？

先在设置重新查看连接配置，确认两个 EXE 同目录、客户端参数分开传递。查询无需开启写权限；写入要在桌面明确开启长期许可，并关闭当前可写仓库或改为只读释放锁。迁移后更新配置并重连。超时后用同一请求 ID 和内容重试，不盲目新增重复请求。

### 关闭应用后有提醒吗？

没有常驻后台或系统通知；下次连接仓库时重新计算。已处理提醒不等于完成待办或改变投递阶段。

### 如何报告问题？

先记录复现步骤和错误码，可在“诊断信息”预览并复制脱敏信息。分享截图前遮挡公司、备注、简历和本机路径，不上传真实仓库、快照、审计或备份。帮助中的说明不包含你的实时投递内容。

## 诊断信息

帮助菜单“复制诊断信息…”先打开预览，点击“读取脱敏诊断”后核对，再点击“复制已预览诊断”；不会直接写剪贴板。内容只含固定格式版本、应用/SQLite 版本、支持的数据库版本、操作系统类型、架构、构建类型与当前仓库访问模式（或忙）。不包含仓库 ID/路径、公司名、简历、备注、环境变量、请求或审计内容。读取失败会清除旧预览，复制失败可手动选择文本复制。

“打开日志目录”只尝试打开系统为 OfferTrack 指定的已有日志目录，不接受任意路径、不创建或删除文件。当前版本没有持久应用日志；目录不存在时会明确提示，不代表操作记录丢失。业务历史及 Agent 审计在仓库内，应通过对应页面查看，不能当普通日志公开。

## 关于 OfferTrack

OfferTrack 是离线优先的求职投递管理工具，当前应用版本 0.1.0，采用 MIT 许可证。正式支持目标为 Windows 10/11，macOS 尚未正式支持或验收。本构建仍是开发预览，不是签名安装版；许可证全文显示在本章下方。应用不内置 AI、不自动上传或检查更新。具体平台与性能验收不应由“能够启动”推断。

## 新建数据仓库

1. 启动 OfferTrack，默认进入“概览”。
2. 点击“新建仓库”，在系统选择器中新建或选择一个空文件夹。
3. 成功后，概览会显示仓库位置、格式版本、访问模式和必要的存储风险提示。

OfferTrack 不会在非空文件夹内初始化仓库，以免覆盖或混入已有文件。仓库内会创建数据库、投递附件目录、回收站目录、备份目录和 Agent 交换目录；当前已提供 Agent 只读快照和 JSON CLI。

## 打开已有仓库

点击“打开仓库”并选择包含 `warehouse.json` 和 `offertrack.sqlite` 的目录。应用会校验仓库格式和数据库版本，并记住最近一次成功打开的位置。关闭仓库只释放当前访问，不删除任何数据。

## 写入锁与只读模式

同一仓库同一时间只允许一个 OfferTrack 实例写入。如果另一个实例已经持有写入锁，应用会明确提示，并允许只读打开。只读模式不会执行迁移或写入数据库。

## 存储位置提示

本机固定磁盘上的普通目录风险最低。网络盘、OneDrive/Dropbox/坚果云等同步目录和移动磁盘仍可使用，但应用会显示风险提示。请避免多台设备同时写入同一仓库，并定期将完整备份保存在另一块可靠的本地磁盘。

## 投递记录与视图

“快捷视图”可选择全部投递、准备投递、进行中、待结果、已结束、最近更新，另有回收站页面入口。快捷选择作用于当前投递/归档分区，重置搜索/企业性质/阶段和排序，并退出概览限定范围；列布局、分组、打开的详情草稿及批量勾选不变。最近更新按任意字段最后更新时间倒序，无天数限制；其他快捷项按创建时间倒序。注意勾选仍可能包含当前筛选之外的记录。

“业务状态”可以与搜索、企业性质和阶段筛选组合。它使用稳定阶段及辅助分类，不因“主管面”“等 HR 回复”等改名而失效；已结束是 Offer 或已挂，辅助状态“已完成”不等于 Offer，终态不会同时列入待结果。通过“保存视图”保存业务筛选并设为默认，重新进入后恢复；快捷选择本身不修改数据库，只读仓库也可临时筛选。

在“投递记录”点击“新建投递”，填写公司和岗位。新记录处于“准备投递”，创建日期不可修改。普通单击一行打开右侧详情，在“资料”中修改后点击“保存修改”；当前开发版本还不是表格单元格即时保存。

列设置可拖动排序、调整宽度、隐藏或固定列。搜索、企业性质、招聘阶段筛选可以组合，支持按企业性质、阶段或地点分组。点击“保存视图”，填写名称并勾选“重启后默认使用此视图”，之后重新进入仓库时恢复。多个固定列有独立的固定位置。自定义字段会追加到列设置中。

选择已保存视图后，“更新当前视图”才会把当前临时布局/排序/筛选/分组写回该视图。“重命名视图”只改名称和默认标记；“复制视图”复制已保存的配置，不带入未保存调整，不自动切换当前表格或成为默认。删除视图需确认，只删除显示配置，投递和文件不会删除；当前表格保留为临时视图，若删除默认视图，下次进入使用基础布局。选择“临时视图”只解除当前已保存视图的选择，不重置表格显示。

“刷新视图列表”不会改当前表格布局。修改发生版本冲突时，表单保留输入；先复制需要保留的内容，再取消并刷新列表，之后重新编辑。加载失败会显示“重新读取投递与视图”，不要把此时的缺少记录显示理解成数据被删除。

每页可选 20、50、100、200 条。切换仅影响当前页面，点击“设为默认”才保存仓库级偏好。默认初值为 50。Ctrl+点击表格链接使用系统默认浏览器，普通点击只选择记录。

新建表单、详情资料、阶段/面试/模板、字段、视图和文件夹认领表单的未保存输入会受到保护：切换记录、详情分区、主页面、关闭/切换仓库，以及菜单退出或关闭窗口时，会提示继续编辑或放弃修改。操作进行中不能离开，防止重复写入；失败时保留输入。强制结束进程、系统崩溃不属于这一保护范围，尚不提供草稿自动恢复。表格临时布局/筛选需要另外显式保存为视图，不自动保留。

## 流程与字段

在详情“流程”中选择阶段和辅助状态，可添加并保存面试轮次。首次切换“已投递”自动填入当天投递日期；此后清空日期，不会在下一次切换时重新填入。“已挂”保留最后到达阶段，Offer 自动标记完成。

阶段的“编辑”打开应用内表单，可修改当前投递的名称和颜色，旧历史仍保留当时名称。只能删除尚未使用且不属于当前阶段的自定义阶段，不能删除已有历史的阶段。“保存为流程模板”可填写模板名，并明确选择是否设为以后新建投递的默认模板，不会批量修改已有记录。

“调整阶段顺序”提供上下移动，点击“保存顺序”后只对当前投递生效，不改阶段 ID、当前辅助状态、投递日期、状态更新时间或历史。准备投递固定第一项，Offer 与已挂固定末尾；其余中间阶段可以移动。进度条按当前流程中的位置计算，不代表录用概率；Offer 为 100%，已挂保留最后阶段的位置。

“添加面试轮次”或“编辑轮次”可填写名称、辅助状态、计划时间、完成时间、结果和多行备注；点击保存才写入数据库。时间按电脑当前时区输入和展示，保存时转换成带时区的时间戳；允许清空时间，修改备注不会丢失原时间戳的精度。保存失败时错误会显示在表单中，输入不被清空。遇到版本冲突应先自行保留未保存内容，再关闭详情重新打开，以最新数据重新编辑；目前不提供冲突合并界面。

在“设置”创建自定义字段：文本、数字、日期、网址、布尔、选项。选项字段需要填写逗号分隔的可选值。字段定义属于整个仓库，资料中的字段值只属于当前记录，布尔字段支持“未填写/是/否”。

点击字段旁的“编辑”可改名称、类型和可选值，保存前不写入。中英文逗号均可，重复或空白项会整理；字段名称和选项最多 200 字符。已有记录正在使用的选项不能直接移除，类型变更也必须兼容全部已有值，不会自动清空或转换。保存失败保留输入；版本冲突时先保留内容，再取消并刷新字段列表。当前不提供删除字段。

## 自定义辅助状态

详情“流程”中的“管理辅助状态”只修改当前投递：可改名、添加、排序，以及移除没有被当前进度、面试轮次或历史引用的自定义项。该投递的阶段和轮次共用这组定义，其他公司/岗位不受影响。点击“保存辅助状态”才生效；取消或离开时会检查未保存修改，保存失败保留输入。改名不改变上次状态更新时间，旧历史仍显示当时名称。

新增状态时选定“尚未开始、待参加、待完成、待结果、已完成”之一作为基础分类，供后续提醒/统计识别；保存后分类固定，名称仍可修改。例如“待主管回复”可以归类为“待结果”。已完成只表示当前阶段完成，不等于取得 Offer；失败必须在招聘阶段选择“已挂”，面试轮次的“未通过”不会自动把投递设为失败。内置六项不能移除，失败项名称固定。每组最多 100 项、名称最多 200 字符且不能重名。

流程模板页也有“管理模板辅助状态”，只影响以后新建的投递。保存为模板、复制模板与复制完整记录会带上独立状态定义，不与来源自动同步；新记录仍从“准备投递 / 尚未开始（或该项的新名称）”起步。若已有模板名称或阶段草稿，请先保存或重新载入再编辑模板辅助状态。

## 流程模板管理

侧栏“流程模板”页显示仓库的默认与自定义模板。可修改模板名称、说明、阶段名称/颜色、阶段顺序，并添加或移除自定义阶段；内置阶段不能移除。编辑后点击“保存模板修改”，整份修改一次提交。当前流程上限为 100 个阶段，名称最多 200 字符。

“复制模板”创建独立模板与阶段 ID，不复制投递记录或简历，也不自动设为默认。“设为默认模板”需确认，只影响以后新建的投递。修改模板不会更改已有投递；从模板移除自定义阶段也不删除已复制到投递中的阶段或历史。

未保存时暂不能复制或设为默认；切换模板、重新载入或离开页面会询问是否放弃。保存失败保留输入，版本冲突时先自行保留必要内容，再“重新载入”后编辑。只读仓库允许查看，不允许保存、复制或更改默认模板。向已有投递应用模板，请使用下面的“批量修改”。

## 安全批量修改

1. 在投递表格右侧勾选记录，或点“选择本页”。勾选不打开详情；选择本页会替换旧选择。跨页、搜索或筛选后仍保留已选记录，请留意已选数量，每批最多 200 条。
2. 打开某条详情后，可“选择当前列表中同公司投递”：按公司名称精确匹配当前活跃/归档列表，包含隐藏在其他页/筛选后的同公司记录，不跨分区、不自动纳入以后新增记录。
3. 点“批量修改”。可归档/取消归档、添加标签、修改内置进度或追加模板。添加标签保留原标签；批量阶段按内置标识匹配，每家公司改过的名称在预览里显示。自定义阶段请在单条详情中修改。
4. 模板需“读取模板列表”后选择；仅追加缺少阶段/辅助状态，保留记录本地名称、颜色、原有相对顺序、当前状态、面试轮次和历史。新阶段排在终态之前，进度位置百分比可能因此变化。同名但不同定义、分类冲突或超出 100 项上限会拒绝整批，不自动覆盖或合并。
5. 点“预览批量修改”，逐条核对公司、岗位、ID 和变化。返回调整会作废旧预览；无变化项不重复增加历史或更新时间。
6. “确认备份并保存”先保存数据库快照，再一次性提交整批；任何记录/模板冲突或备份失败都不保存整批。请等待完成，不关闭应用。结果显示备份 ID，可在设置中找到“批量修改前”备份；它不包含附件，也不会改动附件。

保存失败保留输入；若提示版本冲突，请先自行复制要保留的输入，再取消、点击“刷新投递并清除选择”、重新选中和预览。已保存但列表刷新失败会独立提示，只需关闭结果后刷新，不要重做操作。此入口不删除投递、批量移除标签或覆盖历史；不提供一键撤销，必要时从修改前备份恢复到新的仓库目录。

日程功能自数据库版本 9 新增事件版本、截止、轮次关联、地点、会议链接及结果，旧事件的标题、备注、计划/结束/完成时间保留。阶段 4 B 已追加版本 10 的附件重命名日志；此前待办/规则、视图/字段和独立辅助状态保护保持。当前构建会在数据库升级前创建数据库快照，失败则不升级；此快照不含附件，仍应复制完整仓库留底。旧开发构建不支持升级后的数据库。

## 概览、待办与提醒

连接仓库后默认进入真实概览。统计只包含未归档、未删除的投递（含 Offer/已挂）；“活跃投递”是这个集合总数，不等于仍在进行中。近 7/30 天含今天，创建按本机日期，投递数按你填写的投递日期。历史阶段到达只统计实际状态事件，不补算跳过阶段，不给录用概率。

点击指标、阶段分布或每日趋势数字，进入限定为当时记录 ID 集合的表格，单条会打开详情。“清除概览范围”返回当前分区全部记录；此范围不写入保存视图。来源被归档/删除后，显示条数可能比点击时少。概览底部显示当前仓库信息。

侧栏“待办与日程”提供“待办列表”“招聘事件”“综合日程”。待办可新建通用求职事项，也可关联活跃或归档投递。填写标题、优先级、截止/提醒时间和备注，显式保存；时间按本机时区输入。完成待办会保留时间和备注，可“重新打开待办”。不提供删除按钮。关联归档待办仍在列表但不产生提醒；投递删除后关联待办隐藏，投递恢复后重现。从概览打开待办后可“清除提醒定位”查看全部。

“招聘事件”可新建测评、笔试、面试、签约或其他事件，需选择关联投递，填写计划时间、可选截止、地点、HTTP(S) 会议链接、结果和备注；截止不可早于计划。事件支持完成及重新打开，保留资料；没有删除按钮。会议链接 Ctrl+点击打开默认浏览器，右键可复制或选择浏览器。旧未关联事件编辑时需要选定投递。

面试类型可选择同投递的一个轮次。关联后时间、结果、完成情况以轮次为准，在投递“流程”中编辑，不会双向覆盖；一轮最多关联一个事件。事件保留独立地点/链接/截止/说明。先在事件编辑中选择“不关联轮次”、填写计划时间并保存，才能删除原轮次。若轮次没有计划时间，日程显示无日期而不编造时间。

“综合日程”将待办、事件与面试按日期分组，可按来源筛选；关联事件只列一次，不再重复列原轮次。事件有截止时优先按截止归组，并另显示计划时间，两个时间均可提醒；同一时刻去重。归档事项和终态投递事件不列入日程或提醒，完整资料仍在列表/投递流程。没有关联事件的面试轮次这里只汇总未完成计划，历史请查看投递流程。点击项目打开原待办、事件或投递。

概览的“已逾期事项”“未来 N 天到期事项”“高优先级待办”可打开对应日程集合，N 来自即将到期天数。范围固定为点击时的来源，可清除；空范围不会显示全部。提醒关闭、已处理或推迟不改变这些事项统计。

“调整提醒规则”进入设置，顶部“读取提醒规则”后可修改或关闭七条规则。默认为 3 天无简历、7 天准备未更新、7 天阶段未变化、10 天待结果、3 天即将到期、24 小时紧急和过期立即提示。天数是连续 24 小时，阈值可设 1–8760，逾期只可开关。需要点击“保存提醒规则”才生效；冲突先保留输入，再读取重试。手动提醒时间和高优先级提示独立于七条规则。简历检查只看最近索引中的 PDF/DOC/DOCX 是否缺失，不分析正文。

“本次已处理”仅隐藏当前提醒，不完成事项或改变招聘阶段；“24 小时后提醒”推迟同一提醒。来源元数据、规则版本或紧急程度变化会重新提醒。连接仓库后各页面每分钟、窗口重新获得焦点及页面切换时重算，待办/事件/规则保存后刷新；投递编辑最迟下一次检查反映。其他页面通过“查看重要提醒”返回概览。关闭仓库停止，不后台常驻或发系统通知。应用关闭期间到期事项在下次连接仓库时重算。读取失败保留旧结果并明确报错，不表示数据清空。

## 文件与认领

每条记录独立存放简历。详情“文件”可打开投递目录，直接在资源管理器中放入 PDF、Word 或子目录。文件变化或窗口重新获得焦点会触发索引刷新，也可手动重新扫描；缺失文件不会被凭空恢复。扫描与打开拒绝符号链接和目录联接点。

文件按子目录显示，可以点击目录名折叠/展开。树合并最近附件索引与当前目录观察，空目录标注“空目录”；含缺失附件的分支仍保留，不代表目录一定存在。双击文件名或点击“打开”使用 Windows 默认应用；右键文件或点击“更多”可选择其他应用、在资源管理器定位或复制完整路径。

可写时，在未标记缺失附件的“更多”菜单选择“重命名…”，输入同一目录内的新名称并保存。不接受路径，不覆盖同名文件或保留索引；仅改英文字母大小写时先改为临时名称。改扩展名不等于转换格式，建议保留原扩展名。失败保留输入，可检查占用/重名后重试；处理中不能关闭弹窗。重命名保持附件 ID，不属于表格单格撤销。缺失标记已过期时，先重新扫描。

改名先保存操作日志；若中断后需要恢复，请释放占用再重开仓库。来源/目标不明确或身份不匹配时不猜测、不覆盖；可只读打开后到设置查看“未完成文件操作诊断”。原文件及日志保留，不要自行清理。存在待处理日志时不允许官方 Agent 写入或完整备份/迁移；数据库快照虽可留存，但不能绕过日志直接恢复。

PDF 菜单额外显示已检测到的 Edge、Chrome、Firefox（按常见安装位置检测）；没列出的软件可用“选择其他应用”手动指定。Word 等文档不提供浏览器项。表格网址 Ctrl+点击使用默认浏览器，右键可以复制或选择已检测浏览器；详情中“打开”按钮单击直接打开、右键选择方式。新标签页或窗口由浏览器决定。菜单支持方向键、Home/End、Escape；打开失败显示错误，不修改附件。

“检查目录”只读当前位置，区分缺失、占用、无权限、类型替代或不安全路径。目录可访问不代表全部附件可打开。“重新扫描”才会更新文件索引，只有写入模式可用；扫描失败保留上次索引，确认缺失时只标记，不删除记录或新建空目录。文件回到原相对位置后可重新扫描恢复原索引。缺失标记可能过期，打开文件仍会核对实际位置。

“重试规范化”如果仍失败，会明确提示关闭占用程序或检查重名，不会强制改名。写入打开仓库若因附件扫描/恢复异常失败，可尝试提示中的“只读打开”先查看记录；若仓库必需目录或数据库自身损坏，只读也可能失败。

设置中的“未关联文件夹”扫描 `applications` 直接子目录，默认忽略隐藏和点开头目录。勾选“本次显示隐藏目录和点开头目录（高级）”可临时显示，离开设置后恢复默认；不扫描仓库内部目录、不跟随目录联接点。认领以点击确认的时间创建记录；文件夹占用时先保留原目录关联并标记待规范化，释放占用后可重试。

认领表单取消或 Escape 会检查未保存内容，失败保留输入；创建成功后若重新扫描失败，会单独提示扫描问题，可再次“重新扫描”，不需要重复创建。字段列表与文件夹扫描可分别重试。

## 复制投递

“复制公司信息”只保留公司名称、性质、行业和公司级标签，新记录的岗位留空，请随后填写；不复制原岗位和简历。“复制完整记录”复制已保存的资料、自定义字段、标签、流程结构、面试轮次名称/说明和独立附件副本。新记录从“准备投递”开始，不带入投递日期、归档/删除标记、旧状态历史、轮次的旧时间/结果、待办和事件。

完整复制会先校验文件大小、SHA-256 和目录结构，再提交新记录。请先保存详情中的修改并关闭正在编辑附件的程序；大文件需要更多校验时间。遇到重名、文件占用或校验失败时，不覆盖原始文件。未提交的复制将在重新以写入模式打开时恢复清理；如果临时目录被移动、替换或目录身份无法确认，会保留文件和日志并提示恢复失败，可改为只读查看。不要手动清理 `.copying-` 临时目录；目前尚无可视化修复向导，应先保留仓库副本再诊断。

统计附件大小及复制/校验在后台线程执行，界面会显示阶段等待状态，尚不提供百分比或取消。请等待完成，不要在期间移动附件或强制退出。其他仓库操作可能提示“正在执行操作”，应完成后重试。

设置中的“未完成文件操作诊断”可以在只读模式主动读取。它展示待处理日志的来源/目标相对路径、目录状态，以及是否保存过目录身份；不核验当前身份或文件哈希，也不执行修复、移动或删除。每类最多列出 100 项，超过时提示总数。没有待处理日志并不代表全部附件完好。持续异常时先保留仓库副本，再诊断，不根据此页面自行清理身份不明的文件。

## 归档与回收站

归档只改变记录分区。详情“删除”经确认后将文件夹移动到当前仓库的 OfferTrack 回收站（不是 Windows 系统回收站）。在回收站可恢复，原位置被占用时使用新的安全名称，不覆盖现有目录。

恢复完成后页面显示实际相对路径；发生重名会明确说明原目录未覆盖。成功之后即使列表刷新失败，也不会把恢复说成失败；此时只需“刷新回收站”，不要重复恢复。恢复期间不能重复点击或离开；失败保留条目供检查后重试。

“清空回收站”再次确认后永久删除。确认令牌只绑定当时的仓库和条目集合；期间新增或恢复条目会使确认失效，需重新确认。文件占用或权限错误可能导致部分文件仍保留，应查看结果并重试。删除、恢复、规范化的跨文件系统移动日志会在下次写入模式打开时自动核对；如果来源和目标同时存在等情况无法确定，不擅自覆盖任何副本。

附件“更多”菜单可将单个文件移入独立附件回收站。它不删除投递；恢复保留附件 ID。同名文件或索引已占用原位置时会生成 `restored-…` 名称，原子目录不存在时恢复到投递根目录，均不覆盖已有内容。所属投递已删除时先恢复投递；归档投递不受影响。“清空附件回收站”需另行二次确认，只清理当前仓库已登记附件；外部已经缺失的附件会作为缺失项提示，确认后可清理其元数据。

## 数据库备份与恢复

设置中的“数据库备份与恢复”可“读取备份列表”或“立即备份数据库”。它保存投递、流程、历史、视图、设置和附件索引，不包含 PDF/Word 正文。手动备份成功后即使刷新列表失败也无需重复备份，可再次读取列表。

以写入模式打开仓库、以及跨日后的首次写入时，每个本地自然日自动备份一次；数据库升级前另备份。保留最近 30 个有备份的自然日和 12 个有备份的自然月的代表，过期每日快照移入仓库回收站；手动、升级/迁移/批量修改前快照暂不自动轮换。此处能读取和恢复回收站中的数据库备份。

“清空备份回收站…”仅清理当前仓库 `recycle-bin/backups` 下已识别的标准 UUID 子目录，包括损坏或上次部分清理的目录，不影响活动备份或投递附件。先核对数量和范围，再二次确认永久清理；超过 60 秒、集合变化或目录被替换需重新确认。结果分别列出成功、失败和跳过项；关闭占用程序后可重新清理剩余内容，但失败项中已永久删除的文件不能恢复。未知名称、普通文件及目录联接点会跳过，不提供强制清理。需要保留的内容请先另做完整备份。

点击“校验”检查大小、SHA-256、数据库完整性和版本。“恢复到新目录…”先校验并展示数量，再选择父目录、确认创建全新的恢复子目录。不能选当前仓库或其子目录；原仓库及已有文件不被覆盖，完成后不会自动切换。可通过“打开仓库”查看恢复副本。只读来源也可恢复到新的外部目录。

恢复副本中的投递和附件索引保留，但附件文件需要另行找回；文件扫描会标记缺失，不自动生成空投递文件夹。若快照含未完成的文件移动/复制日志，会拒绝数据库单独恢复，避免跳过日志造成混乱。

未完成的 `.pending-*` 备份、失败的 `.offertrack-restoring-*` 恢复目录会保留，没有自动删除，也不属于“清空备份回收站”的范围。备份损坏、版本不兼容或校验失败时不发布恢复结果。不要手工改清单或清理不明暂存目录。

同盘数据库备份不能防止硬盘损坏，也不包含简历。重要资料请另存完整备份。

## 独立数据库快照恢复

原仓库无法打开时，无需先连接仓库，点击顶部“备份与迁移”，在“独立数据库快照恢复”中操作：

1. 点击“选择并校验数据库快照目录”。选择原仓库 `backups/database` 下的某个快照目录，或已手动复制到其他位置的完整快照目录；目录名可以不同，但里面必须同时有 `manifest.json` 和 `database.sqlite`，不要附加其他文件。这不是选原仓库根目录，也不接受孤立的 SQLite 文件。
2. 核对来源仓库、数据库版本、投递数和附件索引数。版本、哈希、数据库完整性、外键或未完成文件日志检查不通过时不会允许恢复；不要修改清单来绕过检查。
3. 点击“恢复独立数据库快照…”，选择现有父目录并确认。不能选当前仓库或源快照及其子目录。应用再次核验来源，只新建恢复子目录，分配新仓库 ID，不覆盖来源/当前仓库，不合并记录。
4. 成功后显示实际位置，此时尚未切换仓库；点击“打开数据库恢复副本”才打开它，切换失败仍可重试。旧版本升级只发生在副本，源快照保持不动。

此入口与数据库列表恢复一样**不含简历正文**；文件需从另存副本或完整备份找回。若希望投递和简历一起恢复，优先使用下面的完整备份包。

## 完整备份、独立恢复与迁移

点击顶部“备份与迁移”，或打开设置中的“完整备份与迁移”。创建完整备份需要可写仓库；备份的是已保存的数据，请先保存表单并关闭正在编辑简历的程序。默认勾选“包含回收站文件”，取消后只排除回收站文件树，已删除记录元信息仍保留，不会删除源文件。

选择当前仓库以外的已有父目录，应用生成 `OfferTrack-UUID.offertrack-backup`。包包含数据库、简历、空子目录、隐藏/未关联目录和历史数据库备份等普通文件。它不是 ZIP，未压缩、未加密，包含个人隐私，请勿上传公开仓库或 Issue。原本已缺失的附件不会凭空进入备份；文件时间和 NTFS 权限/属性不作为备份内容，记录日期由数据库保留。

原仓库打不开甚至已经丢失时，无需连接仓库即可点击“选择并校验完整备份”。先检查包结构、版本、全部文件长度与 SHA-256，显示文件数、容量和回收站范围；这一步不冒充数据库完整性验收。

点击“恢复已校验备份…”，选择父目录并确认。系统只写新生成的子目录，不覆盖已有内容；重新核对包哈希、提取、验证 SQLite 并升级副本，成功后显示实际位置、投递数和索引数。此时当前仓库尚未切换，点击“切换到已验证仓库”后才打开新仓库；会先检查未保存草稿，切换失败原会话及已完成副本保留，可重试。

“迁移当前仓库…”始终包含回收站，不受手动备份复选框影响。迁移前创建数据库快照，再在目标位置生成完整包并从中恢复新仓库，最后由你确认切换。原仓库和完整包都保留，不自动清理；预留约两份副本的空间。完整恢复/迁移沿用逻辑仓库 ID，历史数据库备份仍能识别，但两份目录的文件和以后修改相互独立，并非同步。

操作显示等待状态、不提供百分比或中途取消。失败的 `.offertrack-backup-UUID.pending` 文件和 `.offertrack-restoring-UUID` 目录保留，没有自动删除或续传。未完成文件日志、文件占用、重解析点、损坏包或不兼容版本会使流程停止。不要在处理期间编辑/移动源文件。含文件数过多、极深或极长路径的包会被明确拒绝，格式限制见 [备份格式](../backup-format.md)。

## 让本地 Agent 分析投递

进入“设置 → 本地 Agent 访问”，点击“生成 Agent 只读快照”。完成后将显示的快照目录交给 Agent，先阅读其 README.md 与 manifest.json。快照包含完整岗位介绍、备注、流程历史、轮次、通用/关联待办、招聘事件和简历的仓库根相对路径，不读取简历正文。

每次发布一个完整新目录，旧快照保留。连接仓库后、每分钟、窗口回到前台和编辑/索引更新后自动检查；可写时仅内容变化才新建，只读只检查。设置“快照新鲜度”显示上次检查和生成时间、相对路径、当前/过期/缺失/错误；检查中或失败时不要认为上次结果仍最新。“检查并按需刷新快照”可主动检查，原“生成”按钮则强制新代。不能把目录名称当作实时同步承诺；Agent 可用 snapshot_status 获取经内容和文件哈希检查的代，或用独立 offertrack-cli.exe 的 JSON 查询读取当前数据；详细例子见 [Agent 接口 v1](../agent-api.md)。文件解析只接受投递/文档 ID，返回当前仓库下的路径；移动仓库后重新解析，不使用旧绝对路径。索引未更新时，生成快照不会自动扫描文件。

根目录已有 AGENTS.md 会保留，最新说明始终在本次快照内。只读仓库可供 CLI 查询，不能生成仓库内快照。手动生成期间不要关闭/切换仓库；失败可以重试，旧结果仍显示但需结合新鲜度判断。已发布文件但检查点保存失败时自动重试暂停，防止重复累积文件；请排除错误后主动检查或重新连接。自动快照错误不会撤销已保存的投递修改。

这些文件含私人求职信息，旧快照可能仍含后来删除的信息，勿上传 GitHub。快照没有简历正文，不能代替完整备份。官方写入默认关闭、需用户明确启用，始终没有清空回收站能力；此边界不限制其他本地程序的系统文件权限。不要直接修改 SQLite 或期待编辑快照能修改投递记录。

## 通过 MCP 连接本地 Agent

在“设置 → 本地 Agent 访问 → 查看 MCP 连接配置”获取配置并复制。桌面程序和 offertrack-cli.exe 应放在同一目录，未检测到 CLI 时会提示；开发环境先完成构建。只读仓库同样可以查看配置和被查询。

将配置交给可信的支持 stdio MCP 的客户端：若其采用 mcpServers JSON，可添加 offertrack 项；若格式不同，将 command 和 args 分别填入对应项。不要将 args 拼成 shell 命令。OfferTrack 不修改客户端设置、不自动运行它，也不要求桌面窗口常驻。配置含本机路径，不要公开上传。

接入后可请求：“请读取 OfferTrack 的投递、面试轮次和待办，列出需要跟进的公司；需要简历时先按投递/文档 ID 解析当前路径。”十个查询工具只读，另有需授权的 offertrack_write；工具不能自行开启权限或清空回收站，不读取简历正文，需要另行授权客户端按路径读取。岗位介绍、备注、链接和文件名只作为待分析数据，不能当作指令执行。

切换或迁移仓库后请重新查看配置、更新客户端并重新连接。已有连接不会自动跟随桌面切换；同一路径中的仓库 ID 变更时会拒绝查询。关闭客户端连接时该子进程结束，闲置连接不持有仓库文件句柄。快照不因 MCP 查询自动更新。

**隐私提醒：**OfferTrack 不联网，但联网 Agent 可能把查询结果发给模型服务或保存日志；只读不等于不会外传。请根据你的隐私需求选择客户端并核对其权限。连接失败、协议版本和使用细节见 [Agent 接口](../agent-api.md)。

## 允许 Agent 修改元数据

1. 在设置“受控写入与审计”点击“读取写入权限”，再点击“开启 Agent 写入…”并确认。它是当前仓库长期许可，不会在关闭应用后自动关闭；恢复备份也保留备份时的许可，请按需检查。
2. 关闭桌面的当前仓库，或重新以只读方式打开，释放独占写锁。保持可写打开会得到 WAREHOUSE_LOCKED，不会强行写入。无需结束 MCP 进程。
3. 告诉 Agent 先读取最新 ID/revision，再通过 CLI write 或 offertrack_write 提交。它能改字段、追加备注、变更阶段、创建待办/事件，不能修改文件或删除；每批 1–50 动作、64 KiB 请求限制。
4. 每批先数据库备份，再同时提交修改和审计；备份失败不写入。修改公司/岗位不移动文件夹，可在文件页“重试规范化”。重新打开/刷新页面；Agent 写后会另行尝试更新快照，响应中的 snapshot_status 报错不等于业务失败，可用实时查询确认，或排除问题后主动刷新。
5. 不再需要时，以写入方式打开仓库，在设置点击“关闭 Agent 写入”。读取权限不会改变其状态；只读模式不能修改许可。

请求超时/断线不代表未提交。要求 Agent **用同一 request_id 和完全相同内容重试**，成功过的请求会返回原业务回执，不重复添加待办；另附的 snapshot_status 是新的检查观察，可能随时间变化。不要直接换新 ID；先查询数据/审计确认。所有官方写入口都受许可限制，关闭后重试同样拒绝。

设置可按需“查看最近 50 条审计”，再逐条查看包含修改前后内容、备份 ID 和原结果的详情。审计是私人业务数据，来源标签由客户端自报，不是身份认证；不要公开上传。成功提交和许可变化有记录，失败请求不提交成功审计。备份页可按“Agent 写入前”找到对应快照并恢复到新目录，不能覆盖当前仓库；数据库备份不含简历正文。

## 导出投递表格

在投递记录或已归档工具栏点击“导出”。默认导出当前筛选的全部页，保持排序；可改为勾选记录（保留勾选顺序、包含筛选外的选中项），或全部未删除记录（含归档、创建时间倒序）。前两种范围在窗口打开时固定，版本变化会拒绝，请关闭并刷新后重试。只读仓库也能勾选导出，不开放批量修改；勾选上限 200 条，筛选/全部最多 10000 条。空筛选只生成表头，不扩大为全部。

默认 XLSX 和当前可见列，可勾选其他隐藏列/自定义字段/文件名；“包含隐藏列和自定义字段”不会自动打开绝对简历路径。路径会暴露本机目录信息，分享前请检查。文件名和路径来自最近提交索引，含缺失标记，不自动读取 PDF/Word 内容、不保证此刻可打开。导出不是完整备份，不含流程完整历史、待办等非表格内容。

选择仓库外父文件夹，OfferTrack 创建全新的 OfferTrack-export-UUID 目录，里面有 applications.xlsx 或 applications.csv，以及 fields.json 字段映射；XLSX 另有“字段映射”页。已有文件不被覆盖；成功后显示两条实际路径。取消选择不产生输出；失败保留输入，写入失败的 .offertrack-export-UUID 暂存保留，不由应用自动删除。

日期时间保留 UTC 精确时间戳，XLSX 单元格全用文本，避免公式和精度自动转换；需要计算的数值可在 Excel 中主动转换。CSV 使用 UTF-8 BOM/引号/CRLF，危险前缀前加单引号以防公式执行，CSV 在 Excel 中仍可能自动转换日期/数字，请用“数据导入”按文本读取。多文件/标签以换行分隔，空值与空文本均显示为空，不承诺无损导回。第一版没有导入功能。

最多 10000 条、256 列、32 MiB 单元格原文；XLSX 每格最多 32767 UTF-16 单元（部分 emoji 占两个）。超限会报错，不默默截断，请减少字段/范围，或将超长备注改用 CSV。文件未加密，勿提交 GitHub。

## 浅色与深色主题

设置顶部“外观”切换，默认浅色。本机 WebView2 偏好长期保存，跨仓库保持，无仓库或只读也可设置；不随数据库/完整备份迁移到其他机器，清除应用 WebView2 数据后会恢复默认。读取失败提示并暂用浅色，保存失败保留之前主题。Windows 原生菜单/文件选择器由系统外观控制。
